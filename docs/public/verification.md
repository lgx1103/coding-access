# 协议兼容与测试

## 支持范围

Coding Access 面向单团队、单实例部署，服务端使用 SQLite。模型额度、上下文容量和可用工具由实际接入的供应商决定。

| 项目 | 说明 |
|---|---|
| 模型接口 | 支持 Chat Completions、Responses 和 Anthropic Messages；跨协议转换不等同于完整的原生接口 |
| 工具搜索 | Responses 转 Chat Completions 支持客户端执行的 `tool_search`、动态工具定义、调用结果与历史回放 |
| 托管工具 | OpenAI 托管工具搜索及其他未适配的托管工具需要原生兼容接入 |
| 对话历史 | 转换通道需要完整历史，`previous_response_id` 不提供跨协议状态恢复 |
| 故障切换 | 在兼容接入间处理重试和切换；请求已经开始输出后，不切换重放 |
| 用量统计 | 使用供应商返回的 Token 用量；未知用量单独记录，不能用于账单结算 |

同一模型配置多个接入时，应核对各接入的模型 ID、上下文与图片能力。模型 ID 按供应商要求填写，保留大小写。Coding Plan、Agent Plan 等不同套餐应分别配置接入地址与密钥。

## 自动化测试

CI 在 Linux、Windows 和 macOS 上运行服务端测试与构建，并在 Windows、macOS 上检查原生客户端。

```sh
npm ci
npm test
npm run build
```

修改原生客户端后，还需安装 Rust 和对应平台的 Tauri 构建依赖，运行：

```sh
npm run test:tauri
npm run check:tauri
```

协议回归测试使用模拟上游。对接新供应商时，还需要用该供应商验证普通对话、工具调用、多轮历史和流式响应。

## 发布前检查

- 服务端：首次部署、旧数据升级、成员权限、备份与恢复。
- 调度：并发占用、流式结束和取消后的释放、限流冷却、故障切换。
- 统计：日期边界、重试计数、未知用量和导出结果。
- 客户端：在目标系统验证安装、工具检测、配置应用、登录和升级。
- 更新包：签名校验、下载取消与重试、安装失败后的恢复。

请在 PR 中说明验证过的系统、编程工具和供应商；日志中删除凭证与私人对话内容。
